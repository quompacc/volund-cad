# U10 – Errors and repairable references made visible

**Status:** accepted on 07.10.2026 after green CI run 440 (`6872928`). The user reviewed
the screenshots ("looks good").

## Starting point

- Errors appeared only as "[Fehler]" / "[blockiert]" in the tree, with the message in the
  tooltip. The timeline showed no status.
- No error offered an action. Stale geometry was marked only in the status bar.
- The boxes in the properties card showed no error.

## Change (user decision 2026-10-07)

- **Markers:** the tree and the timeline mark failed features red and blocked features
  amber. The timeline step carries `featureState` and the message as its tooltip.
- **Error card above the properties (`FeatureErrorCard`):**
  - It shows the message.
  - A blocked feature names the failed feature that blocks it
    (`CadSession::errorCause`, following the inputs) and offers "Zur Ursache".
  - A failed sketch offers "Bearbeiten" and "Reparieren" (reference repair).
  - The card replaces the state message in the old error fields, so all feature kinds
    show their error, boxes included.
- **Stale geometry:** while the view shows the last valid state, a banner at the top of the
  viewport (`StaleBanner`) reads "Zeigt den letzten gültigen Stand – das Modell hat Fehler"
  and offers "Zum Fehler". Bodies are drawn transparent (`SceneBody::stale`).
- **K03:** the button reads "Mit Folgefehlern übernehmen". The rejection message lists
  the affected features. "Alle reparieren" is enabled only while something is broken.

## Checks

- **CI run 440:** green.
- **Windows:** 125/125.
- **Fedora (GCC):** build clean, 91/91 without desktop tests.
- **`desktop.feature_status`** (real window, A-ERR-01 in the UI):
  - Markers in tree and timeline.
  - Banner.
  - A blocked feature names its cause, and "Zur Ursache" selects the failed feature with
    its message.
  - A refresh does not clear the error.
  - After the real repair, banner and markers are gone; the undo of the repair (before
    that) restores the error.
- **Existing tests:**
  - `desktop.reference_repair_flow` and `desktop.document_repair_flow` (A-REF-03 since R06).
  - `desktop.parameter_failure` (keeping with follow-up errors).
- **Screenshots** of the failed and the blocked state were reviewed by the user.

## Limits

- Export and measurement do not exist yet (M12, M17), so there is nothing to lock. The
  face pick is already locked while the model has errors.
- The kernel messages are English, as before.
- A failed extrusion offers no extra button; its properties are the editor.
- Full timeline functions (selection, edit, error states as behaviour) remain M15.
