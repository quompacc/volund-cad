# D11n – Desktop-Duplikataktion

Status: Desktop-Duplikataktion auf beiden Plattformen geprüft.
D11 bleibt `in-progress`. Prüfbasis: `d5ab24d`, 16.09.2026.

## Bedienung

Das bestehende File-Menü enthält jetzt **Duplicate**. Die Aktion verwendet
`CadSession::duplicateDocument()` und anschließend die vorhandene Aktualisierung
von Baum, Viewport und Fenstertitel. Es entsteht kein zweites Fenster und keine
zweite Dokumentautorität. Das aktuelle Fenster zeigt die ungespeicherte Kopie.

Ein sauberes Dokument wird direkt dupliziert. Bei ungespeicherten Änderungen fragt
der Dialog, ob das Original vor dem Duplizieren gespeichert werden soll:

- **Save:** bestehendes Save bzw. Save-As ausführen; nur bei Erfolg duplizieren.
- **Duplicate without saving:** aktuellen Inhalt vollständig übernehmen, Originaldatei
  unverändert lassen. Es werden keine Änderungen aus dem Duplikat verworfen.
- **Cancel:** Dokument, Identität, Pfad, Historie und Titel unverändert lassen.

Der Dialog erläutert ausdrücklich, dass das Duplikat alle aktuellen Änderungen
enthält. Seine zweite Schaltfläche nutzt intern den bestehenden Discard-Buttoncode,
trägt aber die eindeutige Beschriftung „Duplicate without saving“. Der Code bedeutet
hier keine Rücknahme von Modelländerungen.

Das Duplikat hat eine neue DocumentId, denselben Inhalt und Vergabezähler, keinen
Dateipfad und keine Undo-/Redo-Historie. Es ist dirty und trägt den Fenstertitel
`Untitled * — Völund CAD`. Save öffnet danach den vorhandenen Save-As-Dialog.
Benannte Originaldateien werden nicht durch Duplizieren überschrieben.

## Fehlergrenzen

Abgebrochenes Save-As oder fehlgeschlagenes Speichern stoppt die Duplikation vor dem
Identitätswechsel. Ein Fehler in `duplicateDocument()` zeigt den vorhandenen
kritischen Fehlerdialog. Weil D11m auch New um Zufallsvergabe ergänzt hat, fängt
nun ebenfalls die bestehende New-Aktion Ausnahmen aus der Anwendung ab.

Eine erfolgreiche Speicherung vor anschließend fehlgeschlagener Duplikation bleibt
eine erfolgreiche Speicherung des Originals; sie wird nicht rückgängig gemacht.
Die Anwendung veröffentlicht das Duplikat selbst weiterhin erst nach vollständiger
Vorbereitung. D11m prüft den Erhalt fehlerhafter Parameter und veralteter Geometrie.

## Regressionen

Der bestehende Qt-Test `desktop.document_actions` steuert echte QAction-/Dialogpfade:

- Sauberes Duplikat ohne Rückfrage; neuer Namensraum bei identischem Inhalt.
- Dirty-Dialog: Cancel erhält Zustand und Undo; ohne Speichern erhält sämtliche
  Änderungen im Duplikat, lässt die Originaldatei unberührt und aktualisiert den Titel.
- Speichern vor Duplizieren schreibt den vollständigen Originalinhalt; das Duplikat
  bleibt danach ungespeichert. Sein späteres Save erhält die neue ID.
- Abgebrochenes Save-As und Schreibfehler erzeugen kein Duplikat.
- Injizierter Generationsüberlauf in Duplicate und New wird im Fehlerdialog angezeigt;
  Identität, Snapshot und Titel bleiben erhalten.
- Bestehende Unicode-, Open-/Save-/Cancel- und Fehlertitelprüfungen bleiben erhalten.

Die Suite verwendet weiterhin dieselbe Testanzahl, da der vorhandene Desktoptest
inhaltlich erweitert wurde. Es gibt keine neue native Kodierung und keinen neuen
Dateiaustauschfixture; D11m-Lebenszyklustests laufen unverändert mit.
