# L04 – Herkunft, Dependencybudget und Auslieferungsbestandteile abschließen

**Status:** abgenommen am 18.10.2026 – Code `7ea781f`; CI-Lauf 687 grün.

## Entscheidungen (Nutzer, 18.10.2026)

- **PlaneGCS als eigene DLL/.so**, nicht statisch gelinkt. Damit ist die in ADR 0005 offene
  Frage der Verlinkung im Release entschieden.
- **Quellen:**
  - Lizenztexte aller Teile liegen im Paket;
  - die PlaneGCS-Quelle liegt im Paket;
  - unverändertes Qt und OpenCASCADE werden mit Version, Herkunft und schriftlichem
    Quellenangebot genannt.
- **Eigene Lizenz von Völund vorerst offen.** Sie ist im Paket und im Manifest als
  `LicenseRef-Voelund-undecided` ausgewiesen und muss vor L10 entschieden werden.

## Änderung

- **PlaneGCS als gemeinsame Bibliothek** `voelund_planegcs`, in jedem Build:
  - `compat/FCGlobal.h` setzt die Export-Makros;
  - die unveränderten Upstream-Klassen tragen bereits `SketcherExport`;
  - unter Windows liegt die DLL neben den Testprogrammen, `voelund-cad` kopiert sie;
  - installiert wird sie ausdrücklich, ohne Importbibliothek.
- **`packaging/Components.cmake`:** jede Paketdatei gehört über Pfadmuster zu genau einer
  Komponente mit Version, Lizenz (SPDX-Ausdruck) und den nötigen Begleitdateien.
  - Einkompilierte Teile (Eigen, Boost.Graph, Schriften, occt-samples-qt) sind `EMBEDDED`
    und brauchen ihre Texte immer.
  - Die Versionen kommen aus dem Build: OCCT, Qt, Eigen und Boost aus `find_package`, die
    Windows-Bibliotheken aus den vcpkg-SPDX-Dateien.
- **Begleitmaterial im Paket** (`packaging/CMakeLists.txt`):
  - `THIRD-PARTY-NOTICES.md`;
  - `licenses/<komponente>/` mit den vollständigen Texten, Herkunft und SHA-256 in
    `packaging/licenses/README.md`;
  - `source/planegcs/` mit `README-Voelund.md` (Bauanleitung für eine Ersatzbibliothek).
- **Manifest/SBOM aus dem Staginginhalt:**
  - `WritePackageManifest.cmake` läuft als letzter Installationsschritt und schreibt
    `MANIFEST.txt`: Komponenten mit Version und Lizenz, dann jede Datei mit SHA-256 und
    Komponente;
  - `CheckPackageNotices.cmake` vergleicht Manifest und Paket.
- Dokumentation: ADR 0005 (Abschnitt „Release linking“), `docs/provenance/README.md`,
  `freecad-planegcs.md`, `docs/dependencies.md`, `docs/packaging.md`.

## Prüfungen

| Szenario | Nachweis |
|---|---|
| Jede Datei des installierten Pakets gehört zu einer Komponente | `platform.package_runtime` (18.10.: Windows 93 Dateien, 14 Komponenten; Linux 96 Dateien, 7 Komponenten) |
| Jede ausgelieferte oder einkompilierte Komponente hat ihre Lizenztexte im Paket | ebenda |
| `MANIFEST.txt` stimmt mit dem Paket überein (Dateiliste und SHA-256) | ebenda |
| PlaneGCS ist eine eigene Datei (`bin/voelund_planegcs.dll`, `lib64/libvoelund_planegcs.so`), das installierte Programm lädt sie aus dem Paket | ebenda; Linux `ldd`: `bin/../lib64/libvoelund_planegcs.so` |
| Entfernter Lizenztext (`OCCT_LGPL_EXCEPTION.txt`) und entfernte Bibliothek werden mit Namen gemeldet | ebenda (Negativfall) |
| Eine Datei ohne Komponente wird gemeldet | Handprobe: eine Nutzerdatei in `Installer/` → „belongs to no component: Prüf Ordner/Teil mit Ä.volund“ |
| Solver unverändert | `features.planegcs_solver` und alle Skizzentests auf beiden Plattformen |

## Grenzen

- **Keine rechtliche Freigabe.** Die Prüfung belegt nur, dass das vorgesehene Begleitmaterial
  vorhanden ist und zu den Dateien passt. Ob es genügt, ist eine Releaseentscheidung.
- **Quellenangebot:** `THIRD-PARTY-NOTICES.md` nennt noch keine Kontaktadresse („die
  Herausgeber von Völund CAD“). Sie muss vor einer Veröffentlichung (L10) eingetragen werden,
  zusammen mit der eigenen Lizenz.
- **Ersatzbibliothek:** Eine selbst gebaute PlaneGCS muss ABI-kompatibel sein (gleicher
  Compiler, gleiche Klassen). Ein Austausch wurde nicht ausprobiert.
- **Lizenztexte:** Die Texte sind Kopien aus den verwendeten Paketen (vcpkg, Fedora). Bei einem
  Versionswechsel einer Komponente muss der Text verglichen werden; das prüft kein Test.
- Die MSVC-Laufzeit ist nur benannt; sie wird nach den Visual-Studio-Bedingungen
  weitergegeben.
