# M16 – Umordnen und Löschen mit Abhängigkeitsprüfung

**Status:** abgenommen am 16.10.2026 nach grünem CI-Lauf 628 (`4ba2071`).

## Entscheidungen (Nutzer, 16.10.2026)

- **Umordnen:** einen Timeline-Schritt an eine andere Stelle ziehen.
  - Vor seine Eingänge wird abgewiesen und erklärt, bevor sich etwas ändert. Beispiele: eine
    Extrusion vor ihre Skizze, eine Verrundung vor ihren Körper.
  - Spätere Features desselben Körpers werden sichtbar umgehängt, wie beim Einfügen an der
    Marke.
  - Ein Rückgängig-Schritt.
- **Löschen** („Löschen“, Entf in der Timeline, Kontextleiste, Timeline-Menü):
  - Ohne Abhängige wird sofort gelöscht.
  - Mit Abhängigen nennt ein Dialog sie und bietet drei Wege: „Mit Abhängigen löschen“
    (bewusste Kaskade), „Nur dieses löschen“ (Abhängige bleiben mit Fehler zum Reparieren)
    oder Abbrechen.
  - Ein Rückgängig-Schritt.

## Änderung

- **Dokument** (`ModelDocumentReorder.cpp`):
  - `featureReferences` unterscheidet strukturelle von geometrischen Verweisen.
    - Strukturell: Eingang, Körper, Skizzen, Bezugsebenen/-achsen, Muster einer Kopie.
    - Geometrisch: Flächen und Kanten über das Feature, das sie erzeugt hat.
  - `moveFeature`: Ein Muster wandert mit seinen Kopien. Körper-Eingänge des verschobenen und
    der überholten Features werden explizit umgehängt. Was strukturell vor dem Feature stehen
    muss, wird geprüft.
  - `deleteFeatures`: Die Kopien eines Musters gehen mit. Verlorene Körper-Eingänge nehmen
    den Körper, wie er jetzt davor steht. Verwaiste Körpernamen und eine gelöschte Marke
    fallen weg.
- **Anwendung** (`CadSessionHistoryEdit.cpp`):
  - `CadSession::moveFeature` und `deleteFeatures`.
  - `deletionPlan`: zuerst die strukturell Abhängigen, transitiv. Ist darunter mehr als das
    Feature selbst, ist „Nur dieses“ unmöglich. Dann, was ohne das Feature nicht mehr
    auswertet, wiederholt bis nichts Neues mehr scheitert.
  - Es gibt keine Regel „alle späteren Features löschen“: Nur tatsächlich betroffene Features
    stehen in der Liste.
  - `finishCandidate` blendet bei einer Strukturänderung (Löschen, neue Reihenfolge) keine
    Fehler mehr als „unabhängig“ aus.
- **Oberfläche:**
  - Timeline-Schritte lassen sich ziehen; eine gestrichelte Linie zeigt die Lücke.
  - Ablehnungen stehen in der Statuszeile.
  - Entf auf einem Schritt löscht; `history.delete` steht in Kontextleiste und Menü.
  - Der Dialog `deleteFeatureQuestion` nennt die Abhängigen. „Nur dieses löschen“ ist
    gesperrt, wenn sie ohne das Feature nicht bestehen können.

## Prüfungen

| Szenario | Nachweis |
|---|---|
| Verrundung vor die Tasche, Quader ans Ende: Platte unverändert, alle IDs erhalten; Rückgängig | `application.history` |
| Extrusion vor ihre Skizze und Bohrung vor ihren Körper abgewiesen, nichts geändert | ebenda |
| Tasche: keine Abhängigen, geht allein | ebenda |
| Taschen-Skizze: nur mit der Tasche (strukturell); Kaskade, Rückgängig | ebenda |
| Extrusion der Platte: Bohrung, Tasche, Verrundung gelistet, Quader nicht; allein standardmäßig abgelehnt, auf Wunsch mit Fehlern; Rückgängig stellt den ganzen Graphen her | ebenda |
| Oberfläche: Quader-Schritt nach vorn gezogen; Verrundung vor die Extrusion abgewiesen; Entf auf der Extrusion → Dialog nennt die Verrundung, „Mit Abhängigen löschen“; Rückgängig | `desktop.timeline` |
| Befehle | `desktop.command_inventory`, `desktop.command_surfaces` |

## Grenzen

- Mehrere Features auf einmal umordnen oder löschen geht nicht; immer ein Schritt.
- Bei „Nur dieses löschen“ bleiben die Abhängigen mit Fehler stehen. Die Reparatur läuft über
  die bestehenden Wege (Bearbeiten, Referenzreparatur).
