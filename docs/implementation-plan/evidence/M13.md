# M13 – Historische Features bearbeiten

**Status:** abgenommen am 16.10.2026 nach grünem CI-Lauf 619 (`6c5c57f`).

## Befund

Die Modellebene trug A-HISTORY-01 schon:

- Eine frühe Änderung wertet die ganze Kette neu aus, als eine Transaktion mit einem
  Rückgängig-Schritt.
- Eine Vorschau (`previewAction`) rechnet auf einem Kandidaten und lässt das Dokument
  unverändert.
- Die Werkzeug-Panels öffnen beim Bearbeiten die Originalwerte auf dem Körper vor dem Feature
  (`bodyProducerBefore`), nicht auf dem aktuellen Stand.

Es fehlte, Fehler an Nachfolgern ausdrücklich übernehmen zu können. Das ging nur im
Skizzeneditor und im Eigenschaftspanel. Alle Werkzeug-Panels lehnten ab.

## Änderung

- **`SuccessorErrors.hpp`:** Eine Bearbeitung, die nur an späteren Features scheitert, während
  das bearbeitete Feature selbst gültig bleibt, bietet im Panel „Mit Folgefehlern übernehmen“
  an. Scheitert das bearbeitete Feature selbst, gibt es das Angebot nicht; dort muss der Wert
  passen.
- **Alle Bearbeitungs-Panels** (Extrusion/Drehen, Verrundung/Fase, Bohrung, Kombinieren,
  Bezugsebene/-achse, Wandstärke, Formschräge, Spiegeln, Muster, Bewegen):
  - Das Angebot übernimmt dieselbe Aktion mit `keepEditableErrors` über den normalen
    OK-Abschluss des Werkzeugs.
  - Nachfolger bleiben erhalten und zeigen ihren Fehler am Feature.
  - Nichts wird gelöscht; ein Rückgängig stellt die vorherige Kette her.
- **`runCommand`** zählt „mit Fehlern übernommen“ als Erfolg. Das tritt nur auf Anforderung ein.

## Grenzen

- Während ein historisches Feature bearbeitet wird, zeigt der Viewport die Vorschau der
  ganzen Kette, keine zurückgerollte Ansicht. Picks werden gegen den Stand vor dem Feature
  aufgelöst.
- Unterdrücken, Zurückrollen, Umordnen und Löschen folgen mit M14–M16 (A-HISTORY-02).
