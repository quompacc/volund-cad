## Abgeschlossener Teil: Solver-Freigabe

- `SketchEditorSession::canAccept()` verlangt einen erfolgreichen Solve. `failed`
  sperrt jetzt ebenso wie `conflicting` die Bestätigung, unabhängig von eventuell
  noch vorhandenen Freiheitsgraden. Ein direkter Accept-Versuch erhält Dokument,
  History, Clean-Zustand und offenen Editor.
- Beim Öffnen einer bestehenden Skizze wird das Solvergebnis im Editor ermittelt
  und gespeichert. Zuvor wurde im Controller gerechnet, das Ergebnis aber verworfen;
  ein widersprüchlicher Ausgangszustand konnte dadurch zunächst akzeptierbar wirken.
- Fehlende Stützflächen werden beim Öffnen ausdrücklich gemeldet. Die Oberfläche
  unterscheidet numerischen Fehler, Widerspruch und erfolgreiche Unterbestimmung;
  eine alte Freiheitsgradmeldung bleibt bei `failed` nicht stehen.
- Nach erfolgreicher Korrektur wird OK wieder freigegeben. Bestätigen erzeugt
  einen rückgängig machbaren Dokumentstand; Undo stellt den sauberen Ausgang her.

## Regression und Grenzen

`desktop.sketch_solver_gate` verwendet den produktiven Controller und ToolPanelHost
in einem sichtbaren Qt-Fenster. Eine private Friend-Testnaht injiziert `failed` mit
Freiheitsgraden -1, 0 und 4. Geprüft werden Meldung, deaktiviertes OK, direkter
Accept-Versuch und unveränderter Dokumentzustand. Ein vorhandenes widersprüchliches
Constraint-Fixture durchläuft den echten Solver bereits beim Editoraufbau.
Die Reparatur erfolgt über eine echte Linienlängenänderung mit Neuberechnung;
anschließend werden produktives OK und Dokument-Undo geprüft.

Der numerische Fehler ist gezielt injiziert, kein behaupteter reproduzierbarer
PlaneGCS-Konvergenzfehler. Die Bilder zeigen den produktiven Werkzeugbereich in
einem Testfenster ohne sichtbaren GL-Viewport. Sie belegen Meldung und Freigabe,
keine vollständige interaktive CAD- oder Meridian-Abnahme. Die Maßfeldanzeige
wird in diesem Test nicht erneut aufgebaut; geprüft wird die Solverstatusanzeige.
