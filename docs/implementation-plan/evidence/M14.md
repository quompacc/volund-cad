# M14 – Unterdrücken und Zurückrollen als getrennte Zustände

**Status:** abgenommen am 16.10.2026 nach grünem CI-Lauf 624 (`5a313f8`, enthält M14a
`7fc25e8` und M14b). Der Lauf zu `7fc25e8` allein scheiterte an `desktop.drag_flow` („The window
does not become active“), weil parallel lokale Desktop-Tests auf dem Runner liefen; kein Codefehler.

## Entscheidungen (Nutzer, 16.10.2026)

- **Unterdrücken reicht weiter:**
  - Ein unterdrücktes Feature wird übersprungen; spätere Features rechnen auf dem Körper ohne
    es.
  - Wer eine Fläche oder Kante braucht, die nur das unterdrückte Feature erzeugt hat, zeigt
    einen Fehler. Nichts wird umgedeutet.
  - Unterdrückt man einen Körper-Erzeuger (Quader, neue Extrusion), fehlt der Körper; seine
    Features sind blockiert.
- **Rückrollmarke wie in Fusion:**
  - Features hinter der Marke werden nicht berechnet und blass gezeigt.
  - Neue Features werden an der Marke eingefügt, die Marke rückt hinter sie.
  - Die Position wird gespeichert. Verschieben ist kein Rückgängig-Schritt und macht das
    Dokument nicht „geändert“; Rückgängig und Wiederholen lassen die Marke stehen.
- **Bedienung:**
  - „Unterdrücken“/„Aktivieren“ und „Zurückrollen bis hier“ in der Kontextleiste des gewählten
    Features und im Rechtsklickmenü eines Timeline-Schritts.
  - „Ans Ende“ an der Endmarke der Timeline und im Menü.
- **Schema 34:** Kind 32 des Hauptlabels mit den unterdrückten IDs (1) und der Marke (2).

## Unterschied der beiden Zustände

| | Unterdrücken | Zurückrollen |
|---|---|---|
| Gespeichert | ja | ja |
| Rückgängig-Schritt | ja | nein |
| Dokument „geändert“ | ja | nein |
| Wirkung | ein Feature fehlt, spätere rechnen weiter | alles hinter der Marke ruht |
| Löschen | nein | nein |

## Änderung

- **Dokument:**
  - `FeatureDescriptor::suppressed` und `ModelDocument::setFeatureSuppressed`.
  - `DocumentSnapshot::rollbackAfter`: zählt nicht als Modellinhalt (`matchesContent`).
  - `ModelDocument::setRollback`: Ansichtsänderung wie die Körper-Sichtbarkeit.
  - `commitState` fügt neue Features hinter der Marke ein und rückt sie nach.
  - Spätere Features, deren Eingang der Körper vor der Marke war (z. B. eine Skizze auf einer
    Fläche), werden beim Einfügen sichtbar auf das neue Feature umgehängt. Das ist im Dokument
    gespeichert und wird nicht erst bei der Auswertung erraten. Die ältere Zusage, dass ein
    historischer Eingang nicht still auf neuere Geometrie umgeleitet wird, bleibt bestehen.
  - Rückgängig/Wiederholen behalten die Marke.
- **Auswertung:**
  - Status `suppressed` und `rolledBack`; beide gelten nicht als Fehler.
  - `bodyProducerBefore` überspringt unterdrückte Features.
  - `effectiveInput` reicht über einen unterdrückten Eingang hinweg zum Körper davor.
  - Abhängige eines unterdrückten Körper-Erzeugers sind blockiert.
  - Eine verschobene Marke rechnet neu.
- **Anwendung:**
  - `FeatureRuntimeStatus::suppressed`/`rolledBack`: keine Reparatur, keine Fehlerkarte.
  - `SetFeatureSuppressedAction` mit `CadSession::setFeatureSuppressed`; behält Folgefehler
    standardmäßig.
  - `CadSession::setRollback` und `rollbackAfter`.
- **Oberfläche:**
  - Befehle `history.suppress`, `history.rollback_here`, `history.roll_forward`.
  - Rechtsklickmenü der Timeline-Schritte.
  - Unterdrückte Schritte gestrichelt, zurückgerollte blass.
  - Die Marke steht als Strich zwischen den Schritten; die Endmarke ist ein Knopf
    („Ans Ende“).
  - Baum: „[unterdrückt]“ und „[zurückgerollt]“.
