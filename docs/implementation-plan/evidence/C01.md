**Status:** abgenommen am 04.10.2026.

## Aufbau

- `.gitea/workflows/ci.yml`: Job `linux-desktop` je Push und Pull Request auf dem
  selbst gehosteten Runner (`runs-on: linux-desktop`, Host-Executor, Kapazität 1):
  `actions/checkout@v4`, `tools/run-ci-linux.sh`, `actions/upload-artifact@v4`
  (`linux-desktop-<sha>`, auch bei Fehlschlag).
- `tools/run-ci-linux.sh`: projektlokales OCCT aus `~/.cache/voelund/occt-linux`,
  `setup-linux.sh desktop`, `check-source-limits`, danach `run-linux-desktop.sh`
  (Build, vollständiger CTest mit JUnit, Smoke-Aufnahmen) in einer headless
  Wayland-Sitzung `kwin_wayland --virtual` unter `dbus-run-session`, eigenem
  `XDG_RUNTIME_DIR` und ohne `DISPLAY`. `session.txt` weist die Sitzungsart aus.
- Runner: `gitea-runner` v4.1.0 (SHA256 der Release-Datei geprüft), Systemdienst
  `gitea-runner.service` mit `User=eduard`, Konfiguration `tools/ci/gitea-runner.yaml`,
  Einrichtung `tools/ci/install-runner.sh`. Registrierung und Token nur auf dem Host;
  der Registrierungstoken wurde nach der Registrierung gelöscht.
- Instanz `https://gitea.hl.home.arpa`; Fedora vertraut dafür der Homelab-CA.
- `CMakeLists.txt`: CMP0167 NEW (BoostConfig statt des von CMake 4 entfernten FindBoost).

## Grenzen

- Nur Linux je Push; Windows lokal je Paket, FreeBSD je Gate (ADR 0011).
- Ein Branch-Schutz mit Pflicht-Statusprüfung für `main` wird in Gitea vom Nutzer
  gesetzt; direkte Pushes auf `main` erfolgen nur nach grünem Lauf (Arbeitsregel).
- Ein Build je Lauf von Grund auf (≈ 5 min); ccache ist nicht eingerichtet.
